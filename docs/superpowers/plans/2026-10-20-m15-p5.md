# M15 P5 Implementation Plan (Out marking)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
> **Every implementer and reviewer invokes `ponytail:ponytail` before writing or reviewing code** (global rule).

**Goal:** Players are present by default. Keepers and admins mark a player **Out** for a tournament (whole tournament
before it, from the next game on during it) and clear it. An Out player can't be picked, a saved pick of an Out player
is auto-swapped at game start like today's injured pick, and the buy list shows "Out". Players lose self-reported
injuries and attendance. Past games score exactly as before (spec §5.6, §8 P5: t314, t315).

**Architecture:** One migration (`0027_out.sql`): table `public.outs` (stage, athlete, `from_game`, `until_game`),
keeper RPCs `set_out` / `clear_out`, drops `report_injury`, `confirm_injury`, `clear_injury`, `set_attendance`, and
clears every open injury so the retired injury rows only describe the past. The core scorer gets `outs` beside the
time-based `injuries` it already has: an athlete is unavailable for game n if a (stage-matched) Out row covers n, or
(history only) a confirmed injury covered the game's start. The app loads `outs` with the league rows; the tally gets an
Out toggle per player plus a "Players out" card for marking before a tournament; the pick card and buy list honour
Out; Me and the session page lose attendance/injury. A tested rollback file ships with the migration. Tag `m15-p5`.

**Tech Stack:** React 19 + react-router (hash), TypeScript, Supabase (PostgREST + plpgsql), Vitest + Testing Library, PGlite DB tests.

**Spec:** `docs/superpowers/specs/2026-10-19-m15-qol-design.md` §5.6, §6 (P5 goes live between tournaments, so it
never meets a running tournament's open injuries), §8 P5. No papercuts were carried into P5. §9 amendments 1–6: none
touch Out marking; amendment 6's lock-order rule (stage games locked in number order) applies to the new RPCs.

## Rulings (bounded choices the spec leaves open — overturn any in review)

1. **Table `public.outs`:** `id uuid pk default gen_random_uuid()`, `stage_id → stages on delete cascade`,
   `athlete_id → athletes on delete cascade`, `from_game int not null check (from_game >= 1)`, `until_game int check
   (until_game > from_game)` (null = open), `set_by → auth.users on delete set null`, `set_at timestamptz default now()`,
   `cleared_by → auth.users on delete set null`, `cleared_at timestamptz`. Unique index `outs_one_open (stage_id,
   athlete_id) where until_game is null`. An athlete may have several ended rows in one stage (out, back, out again).
   A row covers game n when `from_game <= n and (until_game is null or n < until_game)` — the same rule as roster slots.
   RLS: `select` for `public.can_read_league_data()` (members + staff); writes RPC-only.
2. **`set_out(p_stage uuid, p_athlete uuid) returns int`** (the row's `from_game`). `require_keeper()` first (admins
   included); the athlete must be in the stage's season (`NOT_FOUND` otherwise, also for a missing stage). Locks the
   stage's games `order by number for share`, then `from_game = 1 + coalesce(max(number) where started_at is not null,
   0)`: before the tournament (or before it's opened) = 1; while game N is live or between N and N+1 = N+1. No refusal
   for an over tournament (the mark covers no game). Already out (open row) = no-op returning that row's `from_game`, no
   audit row. Insert uses `on conflict (stage_id, athlete_id) where until_game is null do nothing` so two keepers
   tapping at once both succeed. Audit `('set_out', 'stage', p_stage, {athlete, from_game})`.
3. **`clear_out(p_stage uuid, p_athlete uuid) returns void`**: same gate, same lock. Open row with `from_game` > highest
   started game → deleted (it never covered a game); otherwise `until_game = 1 + highest started`, `cleared_by/at` set
   (games it covered keep their swap). No open row = no-op, no audit row. Audit `('clear_out', 'stage', p_stage,
   {athlete, from_game, until_game})` with `until_game` null when deleted.
4. **No owner gate.** With shares nearly every playing keeper owns part of many players, and marking a player Out never
   helps an owner (it only removes him from picks); keepers are trusted staff and every mark is in History.
5. **Retired:** 0027 drops `report_injury`, `confirm_injury`, `clear_injury`, `set_attendance`. Tables `injuries` and
   `attendance` stay, read-only history (`save_taps` keeps inserting `present` rows; harmless). `private.is_injured` and
   `open_auction`'s supply check are left alone (always false once every injury is cleared).
6. **Past games unchanged:** 0027 runs `update public.injuries set cleared_at = now() where cleared_at is null`. Every
   game that started before the paste keeps its injury swap (the scorer's time-based check still sees the interval);
   nothing after it is affected. Open injuries are **not** converted to Out (spec §6: P5 lands between tournaments);
   the runbook pre-check lists any so a keeper re-marks them Out after the push. Proved by a DB replay test (Task 2).
7. **Notice word:** `GameNotice` `'injured'` → `'out'`, for past injury swaps too ("X was out, so Y played."). The
   matchup strip says "Your pick is out". The sides' own picks are still saved as made (`set_game_pick` doesn't refuse
   an Out player; the core swaps at the start, as with injuries today).
8. **Where keepers mark:** (a) the tally board: each player card's header button (replacing Present/Absent and the
   injury pill/confirm) reads "Mark out" or, when out, an "Out" pill ("Out from game N" while N hasn't started) plus
   "Clear out"; hidden on a closed board (verified or earlier season). Not disabled for "On your team" (Ruling 4).
   (b) a **"Players out"** card on the `/tally` games list, for marking before a tournament: stage = the season's
   earliest stage whose `ends_on` ≥ today (none = no card); heading "Out · <stage>", rows "<name> · from game N" + Clear
   (A→Z), "Nobody is out." when empty, then a `<select aria-label="Player">` of opted-in athletes not out + "Mark out".
   No confirms: each action is undone by the other.
9. **Pick card:** an Out player (Out for the next game) shows an "Out" pill (`pill bad`, replaces "Injured") and a
   disabled Pick button; a saved pick of an Out player keeps its "Your pick · Clear" button. The buy list shows an
   "Out" pill for an open Out row in the buying stage (replaces "Injured").
10. **Me** = `<h1>Me</h1>` + email reminders (no linked-player load, no Injury/Attendance cards). The session page's
    Attendance card goes (nobody marks attendance any more; the stat lines show who played).
11. **History:** `set_out` → "Marked <athlete> out from game N"; `clear_out` → "Cleared <athlete>'s Out" (both in
    `AUDIT_ACTIONS`). Admin power: admins mark and clear like keepers and see every mark in History; nothing new in the
    Admin tab.
12. **Rollback is a tested file:** `supabase/rollback/0027_out_down.sql` (outside `migrations/`, so tests don't apply
    it by default) drops `set_out`, `clear_out`, `outs` and re-creates the four retired functions verbatim from their
    latest versions (0005 `clear_injury`, 0007 `set_attendance`, 0009 `report_injury` and `confirm_injury`) with the
    revoke/grant loop. A DB test applies it after all migrations and calls each restored function.

## Review Focus

1. Out marked while game N is live → covers N+1 on, and game N (already started with that player picked) still plays him on replay. → Task 1 DB test + Task 2 core test.
2. Clearing an Out that already covered a started game ends it (row kept, `until_game` = next game) and that game keeps its swap; clearing one that never took effect deletes it; out → clear → out again works. → Task 1 + Task 2.
3. Two keepers mark the same player at once, or clear twice → one open row, no error, one audit row. → Task 1.
4. A saved pick who is then marked Out is swapped at the start with the "out" notice; if nobody else is free he plays anyway (today's fallback). → Task 2 core test + Task 4 card test.
5. A player (no role), anon, or an athlete from another season → refused / `NOT_FOUND`; deleting the stage or season removes its Out rows. → Task 1.
