# M6 Weekly Play Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Weekly head-to-head play for the whole league year: Mon–Sun weeks per stage, sealed picks that lock at a
set weekday/time, auto-picks for missed/injured/used picks, standings computed from locked stats, stage-based
degradation, rank-based allowances, and hold-to-subtract on the tally board.

**Architecture:** Scoring runs in every browser: `src/core/year.ts` (`scoreYear`) replays the league's year from
league-readable rows and stores nothing, so corrections and reopens need no rescore job. The database only adds
`weeks`, sealed `picks`, and admin RPCs; the allowance RPC now takes ranks computed by the admin's browser.

**Tech Stack:** TypeScript, React 19, Vite, Supabase (Postgres RLS + security-definer RPCs), Vitest, PGlite for DB tests.

**Spec:** `docs/superpowers/specs/2026-09-27-m6-weekly-design.md` (read it first; this plan argues from it).

## Global Constraints

- Every executor invokes `ponytail:ponytail` first (the user's standing rule): shortest correct diff, no new deps.
- node/npm are not on the Bash PATH: prefix commands with `export PATH="/c/Program Files/nodejs:$PATH";`.
- UI follows `DESIGN.md` and uses only tokens from `src/app/tokens.css` (no new colours). Gold means act; pills carry words.
- All writes go through security-definer RPCs; every new RPC writes an audit row; picks and bids stay sealed in audit rows (membership id only).
- Every new migration: explicit `grant select … to authenticated` beside its policies, re-run the function grant loop.
- Pick lock defaults: `pick_lock_day` `mon`, `pick_lock_time` `21:00` (America/New_York). Degradation defaults: `decay_grace_stages` 1, `decay_rate` 0.9, `decay_floor` 0.6. `upset_k` 2.
- Error codes: `WEEKS_HAVE_PICKS`, `INVALID_LOCK_TIME`, `PICK_LOCKED`, `NOT_ON_ROSTER`, `NOT_MEMBER`, `STANDINGS_MISSING`.
- DB tests time out when run alongside the dev server or other agents: run `npx vitest run tests/db` on its own.
- Deploy order: the user pastes `0008_weekly.sql` into Supabase **before** the new site deploys.

## Review Focus

Inputs the spec implies that are most likely to bite real users; each has a test in the owning task:

1. **A season with more than 1000 stat lines** (PostgREST's row cap) must still score every line → `fetchAll`
   paging tests (Task 4).
2. **A keeper's hold on a stat button** must take exactly one off and never also add one when the finger lifts;
   sliding off early cancels; keyboard minus works → `StatButton.test.tsx` (Task 6).
3. **Stage dates edited after its weeks exist** → **Rebuild weeks** follows the new dates (until anyone picks) →
   `rpc-weekly.test.ts` "follows edited stage dates" (Task 3).
4. **An admin or keeper who is also a manager** must not see opponents' picks before the lock → "keeps picks
   sealed" RLS test (Task 3).
5. **A stat line verified late** (after the next week locked) can change a later week's auto-pick on reload; that
   is accepted by the spec, and `scoreYear` must stay deterministic whatever order rows arrive → "is
   deterministic" test (Task 2).

// decay.ts
export function stageMultiplier(stagesStarted: number, s: SeasonSettings): number {
  if (s.decay_mode === 'none') return 1;
  const d = Math.max(0, stagesStarted - s.decay_grace_stages);
  const m = s.decay_mode === 'exponential' ? s.decay_rate ** d : 1 - (1 - s.decay_rate) * d;
  return Math.max(s.decay_floor, Math.min(1, m));
}
// week.ts, inside side():
const multiplier = input.multipliers[pairKey(managerId, athleteId)];
