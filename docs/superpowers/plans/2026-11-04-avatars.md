# Avatars Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** People build a Smiski-inspired sticker character on the Me page, and it shows next to their team in standings, the League matchup header, team pages and the top bar.

**Architecture:** One nullable `profiles.avatar` jsonb, written through two RPCs. A pure `lib/avatar.ts` holds the part lists and turns any stored value into a valid choice; `components/Avatar.tsx` draws a choice as inline SVG, using stored values only as lookup keys. League loaders expose a membership-to-avatar map beside `team` and `owner`.

**Tech Stack:** React 19, TypeScript, Vite, Vitest, Supabase (Postgres RPCs), PGlite for DB tests. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-04-avatars-design.md`. Drawing reference: `docs/superpowers/specs/assets/2026-11-04-avatar-catalog.html` (`build()`, `hat()`, `face()`, `POSES`); port the ideas, not the page's structure.

## Global Constraints

- US English in all new text. Never call the circle behind the figure a "disc": it is "Background color", key `background`.
- No new dependencies. No animation. Nothing on the tally board itself.
- Part keys and labels exactly as in the spec's parts table. Cut parts never return: Hiding, Flopped, Knee hug, Cross-legged, Stretching, Hammer, Bid paddle, Kilt, Stripes.
- A stored value is only ever a lookup key and is never written into the SVG.
- A normal standings row stays no taller than today (about 62px). Long text wraps; never cut it off.
- Sizes are tokens in `tokens.css`; part colors live in `avatar.ts` as art data.
- Tests: `export PATH="/c/Program Files/nodejs:$PATH"` first. Focused: `npx vitest run <file> --maxWorkers=2`. Full suite and builds go through `bash /c/Users/19195/Documents/tribe-heavy.sh <cmd>`.
- Commit messages end with a blank line, then `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

- A stored avatar that is an array, a number, holds unknown keys or holds markup: draws a valid figure and never throws (Task 2).
- Save fails, or is tapped twice: the error shows, the preview stays, only one call goes out (Task 3).
- A removed user's team (`user_id` null) in standings: still a figure, seeded from the membership id (Task 4).
- Signing in as someone else, or a failed profile fetch on token refresh: never shows the last user's figure, and a failed fetch keeps what was known (Task 3).
- A 40-character team name and a "T12" rank at 375px: the avatar keeps 48px, the name wraps, the rank fits (Task 4).
