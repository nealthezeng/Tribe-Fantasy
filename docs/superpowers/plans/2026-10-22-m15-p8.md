**Goal:** The site installs as a phone app (manifest and team-crest icons, an app-shell service worker that never
caches Supabase, an Install entry with an iPhone hint, a code-first sign-in inside the app), and keepers get a bright,
high-contrast tally board for daylight (spec §5.8, §8 P8: t326–t330). Folded in: the P7 final review's
`AuthProvider` hardening (`loading` must always clear).

**Architecture:** Front end only, no migration, no new dependency. A new `public/` holds the manifest and three PNG
icons made once from `src/app/assets/team-logo.png`. The service worker is a hand-written template, `src/sw.js`; a
small Vite plugin in `vite.config.ts` writes this build's cache name and file list on top of it and emits
`dist/sw.js`, so every deploy is a new worker that precaches exactly its own files. `src/app/lib/pwa.ts` registers
it (production only), checks for a new one whenever the app comes back to the front, reloads on the next return once
one has taken over, and keeps the browser's install prompt for the account menu. The bright tally is a
`data-tally="bright"` attribute on `<html>` while the board is on screen, with its values in `tokens.css`. Tag `m15-p8`.

**Tech Stack:** React 19 + react-router (hash), TypeScript, Vite 8, Service Worker + Web App Manifest, Vitest +
Testing Library (jsdom for components, node for the worker).

**Spec:** `docs/superpowers/specs/2026-10-19-m15-qol-design.md` §5.8 (PWA + bright tally), §2 goal 9, §4 anti-goal 4
("The tally board getting slower, animated, or harder to hit"), §6 constraints, §8 P8 (t326–t330). §9 amendments 1–9
checked: none touches P8 (8's polling and 9's guide/help are unaffected; the worker never sees Supabase traffic).

## Rulings (bounded choices the spec leaves open — overturn any in review)

1. **No PWA library.** A ~40-line worker plus a ~15-line build plugin; Workbox would be a dependency for that.
2. **Icons (t326):** the crest centred at 66% of the side on a `#05070a` square (`--bar`, the theme colour):
   `public/icon-192.png` (192×192), `public/icon-512.png` (512×512; the crest lands at ~338 px, its own size, so no
   upscaling) and `public/apple-touch-icon.png` (180×180; iOS fills transparency with black anyway). At 66% the round
   crest sits inside the maskable 80% safe circle, so `icon-512.png` is also the maskable icon. Made once with the
   PowerShell in Task 1 (controller ran it 2026-10-22 and checked the result) and committed; no build step.
3. **Manifest** `public/manifest.webmanifest`, exactly:
   ```json
   {
     "name": "Tribe Fantasy",
     "short_name": "Tribe Fantasy",
     "description": "Fantasy league for our college ultimate team. Every dollar goes to the team fund.",
     "start_url": "./",
     "scope": "./",
     "display": "standalone",
     "background_color": "#080b0f",
     "theme_color": "#05070a",
     "icons": [
       { "src": "icon-192.png", "sizes": "192x192", "type": "image/png" },
       { "src": "icon-512.png", "sizes": "512x512", "type": "image/png" },
       { "src": "icon-512.png", "sizes": "512x512", "type": "image/png", "purpose": "maskable" }
     ]
   }
   ```
   Relative URLs resolve against the manifest's own URL, so `./` is `/Tribe-Fantasy/` (hash routing opens `#/`). No `id`
   (final review: a relative `id` resolves against the start URL's *origin*; without one it defaults to `start_url`). No
   `orientation` (the tally may be used sideways). If the user's home screen cuts "Tribe Fantasy" off (t329), the
   fallback `short_name` is "Tribe".
4. **`index.html`** gains, right after the `theme-color` meta:
   `<link rel="manifest" href="%BASE_URL%manifest.webmanifest" />`,
   `<link rel="apple-touch-icon" href="%BASE_URL%apple-touch-icon.png" />` and
   `<meta name="apple-mobile-web-app-status-bar-style" content="black" />` (the iPhone status bar matches the black top bar).
5. **The worker (t327), `src/sw.js`:** plain JS using the service-worker globals (`self`, `caches`, `fetch`,
   `Request`, `location`; `self.clients`, `self.skipWaiting`). It reads two constants the build writes above it:
   `CACHE` (`'tribe-shell-' + 12 hex`) and `FILES` (this build's files, paths relative to the site, e.g.
   `assets/index-abc.js`). Top comment: what it does, that Supabase never comes through it, and "rollback: see
   docs/setup-supabase.md, M15 P8". `/* global CACHE, FILES */` for ESLint.
   - `install`: open `CACHE`, `addAll` of `['./', ...FILES]` each as `new Request(u, { cache: 'reload' })` (past the
     HTTP cache, so the page and its files come from the same deploy; GitHub Pages caches for 10 min), then
     `self.skipWaiting()`. One missing file fails the install and the old worker stays: that's fine.
   - `activate`: delete every cache whose name starts with `tribe-shell-` and isn't `CACHE` (other apps on
     `nealthezeng.github.io` share this origin's caches: never touch theirs), then `self.clients.claim()`.
   - `fetch`: a request that isn't `GET` or isn't same-origin → `return` (Supabase, Google Fonts, every write go
     straight to the network, untouched). A navigation (`request.mode === 'navigate'`) → `fetch(request)`, and only
     if that rejects (offline) `caches.match('./')`: online users always get the newest page, magic-link and `?code=`
     redirects included, and no navigation is ever stored; a miss there answers `Response.error()`. Anything else →
     `caches.match(request)`, else
     `fetch(request)`. Nothing is written to a cache at runtime.
6. **Build plugin** in `vite.config.ts` (the precache list can only be known at build time):
   ```ts
   /** t327: dist/sw.js = src/sw.js under this build's cache name and file list, so each deploy is a new worker. */
   function serviceWorker(): Plugin {
     return {
       name: 'tribe-service-worker', apply: 'build', enforce: 'post', // post: index.html is in the bundle by then
       generateBundle(_options, bundle) {
         const files = Object.keys(bundle).filter((f) => f !== 'index.html').sort();
         const html = bundle['index.html'];
         const version = createHash('sha256').update(files.join('\n'))
           .update(html?.type === 'asset' ? String(html.source) : '').digest('hex').slice(0, 12);
         const template = readFileSync(new URL('./src/sw.js', import.meta.url), 'utf8');
         this.emitFile({ type: 'asset', fileName: 'sw.js',
           source: `const CACHE = 'tribe-shell-${version}';\nconst FILES = ${JSON.stringify(files)};\n${template}` });
       },
     };
   }
   ```
   Same tree, same `sw.js` (deterministic); any code, CSS, image or `index.html` change, a new one.
   (Build rulings: every worker lookup passes `{ ignoreVary: true, cacheName: CACHE }`: vite preview's `Vary: Origin`
   left the offline shell blank, and reads stay inside this deploy's cache.)
7. **Update path:** `registerServiceWorker(sw, ownUrls, reload)` registers `sw.js`; on every `visibilitychange` to
   `visible` it calls `reg.update()` (a failed check, e.g. offline, is ignored), because an installed app is resumed,
   not reloaded, and hash routing never navigates. On `controllerchange` (a new worker took over) it only notes the
   change; on the **next** return to the front it asks `caches.match(u, { ignoreVary: true })` for each own URL: `import.meta.url` (the
   running bundle's own file) and the page's same-origin stylesheets: any missing means this page is an older build, so it
   reloads, unless it is offline or the tally board is on screen (final review: never reload a keeper's board mid-game
   or offline; it waits for a later return); a page that is already the new build (a cold start after a deploy) is
   found and never reloads. (Build ruling: the check can't run at
   `controllerchange` itself, because the controller changes before the new worker's activate step deletes the old
   shell.) Never reloads while someone is using it. Taps are safe across that reload: the queue is in localStorage and `save_taps` is
   `on conflict (id) do nothing`. Overturnable to a "New version · Reload" notice.
8. **Production only:** `startPwa()` registers the worker only when `import.meta.env.PROD && 'serviceWorker' in
   navigator`; a failed `register` is ignored (the site works without it). Dev, the sim and tests never register.
9. **Install (t328):** an "Install app" item in the account menu, after Rules/Admin and before the theme item, shown
   only when the app isn't already running installed (`isStandalone()`) and either the browser has offered an install
   prompt (Chrome, Edge, Android: `beforeinstallprompt`, kept with `preventDefault()` from `startPwa()`) or it's an
   iPhone/iPad (`isIos()`: `/iPhone|iPad|iPod/` in the user agent, or `Macintosh` with `maxTouchPoints > 1`). Tapping
   it with a prompt closes the menu and shows the browser's install dialog (the prompt is single-use: it's dropped
   after, and on `appinstalled`); on iOS the item is replaced in place by
   `<p className="account-hint">In Safari, tap Share, then Add to Home Screen.</p>`, which takes focus (`tabIndex={-1}`,
   final review). Nothing on other browsers.
   Signed-out visitors have no menu and use the browser's own menu (overturnable).
10. **Signing in inside the installed app (t329 support):** iOS gives a home-screen app its own storage, so a Safari
    sign-in doesn't carry over, and the email's link opens the browser, not the app. When `isStandalone()`, the
    LoginPage's "Code sent" notice reads "Code sent to **email**. Type the code from the email here: its link opens
    your browser, not this app." In a browser it is unchanged.
11. **Bright tally (t330):** on by default, toggled on the board, remembered per device. The board (`TallyBoard`, not
    the `/tally` games list) sets `document.documentElement.dataset.tally = 'bright'` while mounted and on, and removes
    it when turned off or unmounted (← Games, a tab, Back). Key `tribe.tally.bright`: `'0'` = off, anything else or a
    read that throws = on; a write that throws keeps the choice for the visit. The toggle is a `button.secondary` in
    the tally bar's status row, labelled with what it switches to ("Normal board" / "Bright board"; final review: "Dark
    board" was wrong for light-theme phones), like the menu's
    Light mode / Dark mode; it sits away from the stat tiles (anti-goal 4). In `tokens.css` the light block's selector
    becomes `:root[data-theme='light'],\n:root[data-tally='bright']` (bright starts from light mode), followed by:
    ```css
    /* t330: the tally board in daylight. Light mode plus more contrast: white page, black type, dark edges, no glow or glass. */
    :root[data-tally='bright'] {
      --bg: #ffffff; --surface: #ffffff; --surface-2: #eef2f6;
      --fg: #000000; --muted: #39424c;              /* about 10:1 on white */
      --line: #aab4bf; --line-strong: #1c232b;      /* stat-tile edges you can see in the sun */
      --bg-ambient: none; --pane-bg: #ffffff; --pane-border: #aab4bf;
      --pane-shadow: 0 0 transparent; --pane-blur: none;
      --sticky-bg: #ffffff; --card-solid: #ffffff; --notice-bg: #e3f1fc;
    }
    ```
    The top bar keeps `--bar` (black). Nothing fades on the switch (the tally bar's buttons already have
    `transition: none`).
12. **AuthProvider (P7 review fold-in):** `loading` starts as `Boolean(supabase)`, and the `getSession()` chain ends
    `.catch(() => {})` (a failed check reads as signed out; the next auth event retries) then
    `.finally(() => setLoading(false))`, so a throwing `loadProfile` or a rejected `getSession` never leaves every page
    on "Loading…".
13. **Admin powers:** none needed. Install, the bright board and the shell cache are per device; nothing is stored
    server-side; updates reach every phone on their own (Ruling 7). **Destructive actions:** none the user takes. The
    automatic reload on return (Ruling 7) can drop a half-typed form if a deploy landed while the app was in the
    background; taps are never lost. No confirm (not a user action); overturnable to a Reload notice.
14. **Rollback:** reverting the P8 commits is not enough: a browser that gets a 404 for `sw.js` keeps the old worker.
    Revert, then add `public/sw.js` with the self-removing worker below and push; leave it there a few months:
    ```js
    // Removes the Tribe Fantasy service worker (M15 P8) from every phone that installed it.
    self.addEventListener('install', () => self.skipWaiting());
    self.addEventListener('activate', (event) => event.waitUntil(
      caches.keys()
        .then((keys) => Promise.all(keys.filter((k) => k.startsWith('tribe-shell-')).map((k) => caches.delete(k))))
        .then(() => self.registration.unregister()),
    ));
    ```
    The bright tally and Install item go with the revert; no data changes.
