# M14 Admin Power Overhaul Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Admins can see inside every league (sealed info included), give/take player shares, rename teams, fix display names, remove problem accounts and read the admin history — all from the Admin tab.

**Architecture:** One additive-where-possible migration `0024_admin_powers.sql` (roster rows gain a game range, memberships can be "removed", five admin RPCs, two RLS tweaks). Scoring stays in the browser: `src/core/tournament.ts` learns slot ranges and removed teams. Three Admin tab panels: a league browser (Leagues), Users (replaces Keepers), History.

**Tech Stack:** Supabase Postgres (plpgsql RPCs, RLS), PGlite DB tests, React 19 + react-router 8, Vitest + Testing Library, TypeScript.

**Spec:** `docs/superpowers/specs/2026-10-19-m14-admin-design.md` (read it; this plan argues from it).

## Review Focus

1. **Mid-tournament share edit must not rescore finished games** — removing a player after game 2 keeps their game 1–2 points for that team. Test: T2 "slot ending at game 3 still scores games 1–2".
2. **Removing an account must not cascade-delete the team, ledger, pairings or picks** — Test: T1 "admin_remove_user keeps team, donations, pairings; unlinks athlete".
3. **Removed team in an already-paired next game** — the opponent still plays, the removed side scores 0, and Finish's next pairings exclude it without `PAIRINGS_INVALID`. Tests: T1 check_pairings accepts pairings without the removed team; T2 forfeit + pairing exclusion.
4. **A removed team frees its league spot but its name keeps the unique slot** — joining with the same team name still gets `TEAM_NAME_TAKEN` (accepted); max_members counts only live teams. Test: T1 join after removal.
5. **Remove → re-add the same player in one game window** never violates the roster unique key and leaves exactly one live row. Test: T1 "remove then add then remove at the same next game".
