**Goal:** The Stats tab becomes one tournament's sortable player table with a tournament switcher, a game-by-game
player page, an "All stats" fold listing the tournament's games (game pages keep the keeper tools, admins keep the
CSV), and a Tally button on every open game.

**Architecture:** Front end only, no migration. One new lib file holds the pure table helpers and the per-tournament
loader; one new component file holds the sortable table and the tournament switcher, shared by Stats, the game page
(`/stats/:id`) and the new player page (`/player/:athleteId`). The selected tournament lives in the URL (`?t=<stageId>`),
the tally's game in `?game=<sessionId>`, so links and Back work. Ships as tag `m15-p2`.

**Tech Stack:** React 19 + react-router (hash), TypeScript, Supabase (PostgREST), Vitest + Testing Library.

## Rulings (bounded choices the spec leaves open — overturn any in review)

1. **"All stats" = a fold below the table listing the selected tournament's games.** The tournament switcher picks
   the tournament (whose record is the main table); a game in the fold opens its game page `/stats/:id`, which shows
   the same sortable table plus today's keeper tools (verify, reopen, correct, delete). No second table or filter set.
   The fold starts open for keepers when the tournament has an open game. Admin "Download CSV" moves into the fold,
   unchanged (whole season, every session).
2. **Tournaments listed** = stages of the current season whose auction has run (they're the only ones that can have
   games), newest first. Default = `pickPlayingStage` (the tournament being played, else the latest). An unknown `?t=`
   falls back to the default.
3. **Default sort** = points, high first. Stat and points columns sort high first, a second tap flips; the Player
   column sorts A→Z first. Ties fall back to name A→Z.
4. **Player page** = one row per verified game of the tournament, in game order (not sortable); a game where the
   player has no line shows zeros (lines only exist for players with taps). No total row (the Stats table has it).
5. **Sessions with no game** (pre-tournament-mode practices) no longer show on Stats; the admin CSV still includes them.
6. **Tally deep link:** `/tally?game=<sessionId>` opens that game's board; "← Games" clears it. The Stats head keeps
   the plain Tally button (the picker, where Start game lives).
7. Deferred from P1, fixed here: a keeper with no season still sees the Tally button (head renders before the loads).
   `fmt`/`record` → lib stays parked for P3 (P2 doesn't use them).

## Review Focus

1. A tournament whose only game is live (none verified): the table says no stats yet, and the fold lists the game with a Tally button for keepers. → Task 4 test.
2. A stale or foreign `?t=` (stage deleted, other season): falls back to the current tournament, no crash. → Task 1 test (`pickStatsStage`).
3. No tournament yet (season exists, nothing auctioned) or no season: "No tournaments yet." / "No season yet.", and a keeper still sees the Tally button. → Task 2 tests.
4. A player who only turned it over (negative points) and players tied on points: high-first puts the negative last; ties read A→Z. → Task 1 test.
5. `/player/<id>` for an athlete not in this season (old link): a plain "not in this season" message with a link back to Stats. → Task 3 test.

  - `interface TournamentStats { stages: StatsStage[]; stage: StatsStage | null; games: StatsGame[]; lines: LineRow[]; names: Map<string, string> }` (`stages` newest first)
  - `async function loadTournamentStats(seasonId: string, wanted: string | null, today = todayLocal()): Promise<TournamentStats>`
