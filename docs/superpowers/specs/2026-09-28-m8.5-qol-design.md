Goal: fix setup mistakes and League-tab friction the user hit while testing, before the fall beta (auction Oct 18).

Build order: §1 → §2 (DB + small UI) → §3 (nav) → §4 (League block, needs the §4 `place_bid` change).

## 1. Rename and remove athletes (t77, admin only)

- **`rename_athlete(p_athlete uuid, p_name text)`**: `require_admin`; name through `private.clean_name(p_name, 60)`;
  `NOT_FOUND` if no such athlete; unique `(season_id, name)` violation → `ATHLETE_EXISTS` (existing code + message).
  Audit `rename_athlete` with `{old, new}`. Everything references the athlete id, so a rename touches nothing else.
- **`delete_athlete(p_athlete uuid)`**: `require_admin`; lock the athlete row (`for update`), `NOT_FOUND` if missing.
  Refuse with new code **`ATHLETE_IN_USE`** if ANY row references it: `stat_taps`, `stat_lines`, `attendance`,
  `injuries`, `bids`, `roster_slots`, `picks` (every FK to `athletes`, all `on delete cascade` — the check is what
  stops history being wiped). Otherwise delete; audit `delete_athlete` with `{season_id, name, user_id}`.
  A linked account is not "use": the link just goes with the row.
- **UI** `src/app/pages/admin/AthletesPanel.tsx`, per row:
  - **Rename**: swaps the name for an inline input + Save / Cancel (Enter saves, Esc cancels). Errors show in the
    panel's existing error line.
  - **Remove**: `window.confirm("Remove <name>? This can't be undone.")` (same pattern as StagesPanel), then
    `delete_athlete`. On `ATHLETE_IN_USE` the message is "This athlete has stats, bids or picks, so they can't be
    removed. Opt them out instead."
- `src/app/lib/rpc.ts` gets `renameAthlete`, `deleteAthlete`; `errors.ts` gets `ATHLETE_IN_USE`.

## 2. Delete an accidental session (t78, keepers and admins)

- **`delete_session(p_session uuid)`**: `require_keeper` (admins pass it too). Lock the session row (`for update`);
  `NOT_FOUND` if missing; `SESSION_VERIFIED` if `verified_at` is set; new code **`SESSION_NOT_EMPTY`** if any
  `stat_taps` row exists for it. Otherwise delete (attendance rows cascade — harmless for an accidental session).
  Audit `delete_session` with `{season_id, kind, held_on}`.
- **Race**: the row lock serialises with `save_taps` — a tap insert's FK check takes `KEY SHARE` on the session row,
  which conflicts with the delete. Either the tap commits first (then `SESSION_NOT_EMPTY`) or the tap fails after
  the delete (session gone).
- **Taps queued on another phone** for a deleted session: `save_taps` answers `NOT_FOUND`, which `tally/queue.ts`
  already treats as a permanent rejection — the batch is dropped and the keeper told. No change needed.
- **UI** `TallyPage.tsx` `SessionPicker`, "Open sessions" list: a secondary **Delete** button next to Tally on every
  unverified session, HIDDEN when this phone has unsaved taps for it (`unsaved.has(s.id)`). `window.confirm("Delete
  the <session title> session? This can't be undone.")`, then `delete_session`, then reload the list.
  Message for `SESSION_NOT_EMPTY`: "This session already has saved taps, so it can't be deleted."
- Out of scope: changing a session's "counts" flag after creation (no RPC for it today). Add if the beta needs it.

## 4. League tab: combined credits + auction block (t80)

### Rule change (user ruling 2026-09-28)
Your bids in a stage may **not total more than your balance**. This replaces M5's "your total can go over; the
auction gives you what you can afford" (M5 spec §99).
- **`place_bid`** (replaced in 0010, same signature): after the existing checks, lock the membership row
  (`select … from public.memberships where id = p_membership for update`) so two simultaneous bids can't both pass,
  then refuse with the existing **`INSUFFICIENT_CREDITS`** when
  `p_amount + (sum of this membership's OTHER bids in this stage, excluding p_athlete) > private.balance(p_membership)`.
  Changing an existing bid replaces its old amount, so raising one bid within budget still works.
- `run_auction` keeps skipping unaffordable bids (safety net: an admin can lower a balance mid-auction).
- Copy updates: `AuctionCard.tsx` (the "Your total can go over that…" sentence goes), `RulesPage.tsx:68` (bids may
  not total more than your balance; keep "a bid you can't afford by its turn is skipped"), `errors.ts`
  `INSUFFICIENT_CREDITS` → "Not enough credits for that bid.", M5 spec line 99 amended with a pointer here (done with this spec).

### Layout
`HomePage` currently renders per membership: team card (name, league, balance, `Wallet`) → `AuctionCard` →
`WeeklyCard`. New: `HomePage` passes the team card's contents to `AuctionCard` as `children`, and `AuctionCard`
decides the layout from the auction phase:

- **Loading / no stage yet**: renders the team card exactly as today (so nothing flashes while loading).
- **Bidding open** — ONE `<article className="card">`:
  - **Sticky header** (`position: sticky; top: 0` — the black top bar is NOT sticky, it scrolls away, same as the
    admin `.subnav`; z-index above list rows; solid background; the card must not get `overflow: hidden`):
    team name · "Bidding on **N** players · roster **R**" · **credits left** = balance − total of your bids,
    large number (`.big`). R = `roster_size` from season settings (already parsed alongside `min_bid`).
  - Below it: league/season line, `Wallet` (Credit history `<details>`, unchanged), then the bid list inside
    `<details open={no bids yet}>` with summary "<Stage> auction · closes <time left>".
  - The header stays visible while the whole block is on screen; it scrolls away with the block (sticky within its
    card), so WeeklyCard below is never covered.
- **Not open yet / closed / run**: team card as today, then the auction as ONE collapsed `<details>` card whose
  summary is "<Stage> auction · <status pill>" (Not open yet / Bids closed / Done). Expanded content = today's
  per-phase content (roster, every team, fill seed).

### Over-budget bid
- `BidControl` gets `available` = balance − (sum of your OTHER bids), and `onOverBudget()`.
- On submit: if `amount > available`, do NOT call the server; call `onOverBudget()` and show under the input
  `<small className="error">Not enough credits: you have {available} left.</small>`. The button stays enabled
  (so the attempt is possible and gets feedback); the existing min-bid validation still disables it.
- `onOverBudget` (in AuctionCard) bumps a counter used as the React `key` of the credits-left number, restarting a
  CSS animation class `.flash-bad` (≈3 red pulses over ~1 s, colour from tokens.css). Under
  `prefers-reduced-motion: reduce` no animation: the number is simply shown in the error colour. The message above
  lives in a `role="alert"` region so screen readers announce it.
- A server `INSUFFICIENT_CREDITS` (e.g. stale tab) triggers the same `onOverBudget()` + message.
- New CSS goes in `styles.css` using `tokens.css` variables only; keep the phone `@media` block LAST.

## 5. Testing

- **DB** (PGlite, fixed fixture dates — no `now()`-sensitive assumptions):
  - `rename_athlete`: renames + audit; `ATHLETE_EXISTS` on a clash; `NOT_FOUND`.
  - `delete_athlete`: deletes an unused athlete + audit; `ATHLETE_IN_USE` for each of: a tap, a bid, a roster slot,
    a pick (one case per table family is enough: stats, auction, weekly); `NOT_FOUND`.
  - `delete_session`: deletes an empty unverified session + audit; `SESSION_NOT_EMPTY` with one tap;
    `SESSION_VERIFIED`; keeper allowed, plain user `FORBIDDEN` (via the gate test).
  - `place_bid`: second bid pushing the total over → `INSUFFICIENT_CREDITS`; raising an existing bid within budget OK;
    exactly-equal total OK.
  - `rpc-gate.test.ts`: `delete_session` joins `KEEPER_CALLABLE`; audit-row steps added for the three new RPCs.
- **App** (vitest + testing-library): over-budget submit doesn't call `placeBid`, shows the message, re-keys the
  number; Admin link only in the menu, only for admins.
- **Manual** (preview, throwaway season, never the live "Spring 2027" data): rename/remove, delete session, sticky
  header on a 375×812 phone viewport + desktop, flash, reduced motion.
