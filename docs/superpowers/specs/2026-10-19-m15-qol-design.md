# M15 — Quality of life (design)

Date: 2026-10-19. Base: main **after M14 ships** (M14 admin overhaul is mid-build on `m14-admin`; M15 starts from
main once M14 is live). Branch for this document: `m15-qol`.
Status: agreed in chat 2026-10-19, awaiting the user's review of this document. Build plan is written AFTER M14 ships
(M14 rewrites the roster, scoring-loader and admin files M15 touches; a plan written today would go stale).

## 1. Why

New players told the user the app is "hard to understand": general readability and clutter. During a tournament the
League tab stacks everything (scoreboard, pick, shares, standings, leaderboard toggle, games, settings) in one column.
Managers only learn how a game went after a keeper verifies it, there is no way to compare players across games, and
admins create games one at a time as each finishes. M15 makes the app calmer, more live, and easier to start with.

## 2. Goals

1. **League tab = your current head-to-head**, nothing else competing with it during a tournament.
2. **Live feedback**: live (unofficial) scores and your players' stats during a game, with an ESPN-fantasy-style
   animation of what changed since you last looked.
3. **Stats tab** merges Stats and Tally: per-tournament player table sortable by any stat, player game-by-game
   breakdown, an "All stats" record per tournament and per game.
4. **Leaderboards tab**: standings, all-leagues leaderboard, tap any team to see its players, past tournaments.
5. **Real names**: the owner's real name in small text under team names (matchup, standings, team page).
6. **Admin sets up a tournament's games in one go** (a game count, editable) and fills opponents any time.
7. **Players are present by default**; keepers/admins mark a player **Out** per tournament. Players no longer report
   their own attendance or injuries.
8. **Easier to start**: first-visit guide, "?" help on jargon, stats while buying, quieter empty states, a shorter Rules
   page whose numbers match Settings.
9. **Extras**: install as a phone app, owners rename their team, a bright tally for daylight, fix the off-screen
   "needs you" dot.
10. **Last: a final UI overhaul** as clean-up across the whole app.

## 3. Non-goals

- Push notifications or SMS (email stays the only channel, M10 decision).
- Real-time sockets: live data is fetched by polling (my call, see §5.3).
- Trades (dropped for good 2026-10-06).
- New scoring rules. Scores are computed exactly as today; M15 only shows them sooner.
- Admin powers already delivered by M14 (league browser, roster editor, remove user, admin rename, history).

## 4. Anti-goals (fails even if it works)

- The League tab mid-tournament still needs scrolling past standings or shares to find your matchup.
- A live number shown as if it were final. Live numbers are always labelled unofficial until the game is verified.
- Past games scoring differently after M15 (the Out change must not rewrite history, §5.6).
- The tally board getting slower, animated, or harder to hit (tally stays exempt from motion, DESIGN.md rule).
- New users still needing to read the whole Rules page before they can buy or pick.

## 5. What gets built

Standing rules for every part: each change says what power admins get over it ([admin-power rule]); every destructive
or permanent action has an undo, else a specific confirmation ([undo-or-confirm rule]). UI follows DESIGN.md +
tokens.css. Player-facing word is "game", not "session".

### 5.1 Navigation

- Bottom dock / top tabs become **League · Stats · Leaderboards**. The **Tally tab is removed** (keepers reach the
  tally from Stats, §5.4). Me, Credits, Rules, Admin stay in the avatar menu.
- Routes: `/` League, `/stats`, `/leaderboards`, `/team/:membershipId` (team page), `/player/:athleteId` (player
  breakdown; my call to make it a route so it can be linked from anywhere). Old `/tally` redirects to `/stats`.
  The dock stays hidden on the tally board (`body:has(.tally-bar)`, as today).

### 5.2 League tab

Order during a tournament (agreed):
1. Team switch (only with 2+ teams), unchanged except the dot fix (§5.8).
2. **Matchup headline** for the current game (live > next > last, as today's `focusGame`): both team names, the
   **owner's real name** in small text under each, the score (live or final), and each side's starters with their
   stat line so far and points. Live state shows the pulse and an **"Unofficial"** label until verified.
3. **Next-game pick** directly under it (today's PickGame; it already lists your roster with factors, so it is the
   roster view once buying closes).
4. **Buy shares card only while buying is open.** Once buying closes the shares card leaves the League tab (the
   "Every team" split moves to team pages, §5.5; your roster lives in the pick card).
5. **Games this tournament**, compact, below; earlier games further down or folded (builder's call on exact form).
6. League settings, folded, at the bottom (unchanged).
- **Standings and the all-leagues leaderboard move to the Leaderboards tab.**
- Outside a tournament (no games yet): matchup area says what's next (tournament name + date), then the buy card if
  open. No empty standings anywhere (§5.7).

### 5.3 Live scores and the "since you last looked" animation

- **Live data (DB)**: today managers can't read `stat_taps` (keepers only) and `stat_lines` exist only after Verify.
  Add a SECURITY DEFINER read RPC (e.g. `live_game_taps(p_game)`) callable by anyone who can read the league's data
  (`can_read_league_data()`), returning the taps of a **started, not yet verified** game: athlete, stat, tapped_at,
  undo link, and an opaque per-game keeper number (1, 2, …) **instead of keeper user ids**. The browser nets undos and
  runs the same tap-merge the verify screen uses (`tap_merge_seconds`), then scores with the existing core scorer.
- User accepted: live counts can be a bit off (two keepers tapping one play) and may **shift down at Verify**. Once
  verified, the verified lines replace live numbers and are final ("lock when verified").
- **Refresh**: poll every ~15 s while a live game is on screen and the tab is visible; stop otherwise (my call; no
  Supabase Realtime).
- **Since you last looked** (user chose this trigger): per device, remember what you last saw for your matchup
  (per-athlete points and both scores for the focus game) in localStorage keyed by membership + game. On open (and on
  each poll), anything that changed animates: a short **+N / −N chip** on that player's row (gold up, red down) and the
  score **counts** to its new value. First visit = no animation. `prefers-reduced-motion`: chips appear without motion.
  Storage failures fall back to no animation (never an error).
- Admins: see live data for any league they can browse (M14 league browser shows the same live matchup; my call).

### 5.4 Stats tab (Stats + Tally merged)

- **Main table = one tournament's totals** (user: per tournament, not the whole season). Opens on the current or most
  recent tournament with a switcher for earlier ones (my call). Columns: player, each stat in `stat_weights` (G, A, D,
  C, T…), fantasy points; **tap a column header to sort** (desc first; tap again flips). Includes the live game's
  unofficial numbers, marked (e.g. a "live" tag on the table), replaced by verified numbers when verified.
- **Tap a player** → `/player/:athleteId`: their game-by-game breakdown for that tournament (one row per game:
  opponent label "vs Duke", each stat, points), with the tournament switcher.
- **Below the table, one "All stats" control** opens the full record: pick a tournament, or one game in it, and get
  the same sortable table. Keep it clean: one control, not a second page of filters. Admins keep **Download CSV**
  there.
- **Keepers**: open games show a **Tally** button here (replaces the Tally tab). Keeper-only things on today's game
  pages (verify, correct a line, reopen) stay where they are, reached from the game in All stats.
- Phone: the table must work at 375 px (sticky player column + horizontal scroll inside the table, never the page).

### 5.5 Leaderboards tab and team pages

- **Leaderboards**: your league's standings (today's Standings) with the toggle to the all-leagues leaderboard; each
  team row shows the owner's real name in small text.
- **Past tournaments** (extra, agreed): a list of this season's finished tournaments below the standings; opening one
  shows its results: each team's record in that tournament and the standings points it gained, plus your games
  (my call on contents).
- **Every team name is tappable** → `/team/:membershipId`: team name, owner's real name, and **just its players and
  each player's total multiplier** (share × tiredness × repeat factor, the same combined factor the pick card shows),
  as it stands for that team's next game (my call: tiredness changes during a tournament). Nothing else (user).
  Sealed things stay sealed: no picks, no credits.
- Removed teams (M14) show "(removed)" wherever names appear.

### 5.6 Out marking (replaces player-reported attendance and injuries)

- Everyone counts as **present by default**. **Keepers and admins only** can mark a player **Out** for a tournament:
  - before it: Out for the whole tournament;
  - during it: Out **from the next game on** for the rest of that tournament (user: keepers mark injuries during
    tournaments);
  - **undo** = clear the mark (affects only games not yet started).
- An Out player **can't be picked** for those games (pick buttons disabled with "Out"), and a saved pick of an Out
  player is auto-swapped at game start exactly like today's injured pick (same notice path, wording "out").
- The buy list shows an **"Out"** pill for players marked Out for that tournament (replaces "Injured").
- **Removed from player accounts**: Me loses the Injury and Attendance cards; `report_injury`, `clear_injury` and
  player use of `set_attendance` are retired (revoke or drop). The tally board's present/absent toggle becomes the Out
  toggle.
- **DB**: a new table keyed by (tournament/stage, athlete) with the first game it applies from, who set it and when;
  keeper/admin RPCs to set and clear; league-readable. **Constraint: past games must score exactly as before** — the
  scorer keeps honouring confirmed injuries for games that started before the cutover (or the migration converts
  them; builder's call, prove it with a replay test). Absent players with no stats already score 0, so attendance rows
  stop mattering for scoring.

### 5.7 Easier to start (from the 2026-10-19 new-user walkthrough)

Walkthrough findings (simulation, phone width): buying is a blind list of names; 12 identical "T1 · 0–0 · 0 points"
rows before any game; after buying closes "Buying closed" appears twice and teams show credits not share %; Rules is
~1,300 words and leads with leave/create rules; jargon (shares, credits, ×factor, tired, Swiss, verified) unexplained
where it appears. Fixes:
- **First-visit guide**: 3–4 plain steps (your team → buy shares in players → pick 2 each game → higher score wins),
  shown once per account/device, dismissible, reopenable from Rules (builder's call on form; no carousel library).
- **"?" help** next to shares, credits, the × factor, tired, repeat factor, verified: a one- or two-line explanation
  in a popover/details (native `<details>` or the existing popover pattern).
- **Stats while buying**: each player on the buy list shows a compact line from their last tournament (e.g. points
  per game) and the name opens the player breakdown.
- **No empty standings**: hide standings (and the leaderboard) until at least one game has counted; say "Standings
  start after the first game."
- **After buying closes**: one "Buying closed" line; teams' players show **share %**, not credits spent.
- **Rules rewrite**: a three-step summary first, then the details folded by topic (season, credits & shares, picks,
  scoring, standings, FAQ). Leave/create-league rules move into the FAQ.
- **Rules numbers out of sync (user report)**: the Rules stat points don't match what the user sees in Settings
  (score weights). Known mechanics: signed out shows `DEFAULT_SETTINGS`; signed in reads the season's settings and
  **multiplies each stat by the tournament multiplier** (`session_multipliers.tournament`, ×2), so Settings G 3 shows as
  G +6 on Rules. Task: reproduce against the live season, then make Rules and Settings agree (decision in §7).

### 5.8 Extras (all agreed)

- **Install as a phone app (PWA)**, former board t246–t249: manifest + icons (team crest), service worker (cache the
  app shell only; never cache Supabase responses), an Install button + iOS "Add to Home Screen" hint, and verify
  sign-in inside the installed app (iOS storage is separate from Safari → use the 6-digit code login).
- **Owners rename their own team**: owner-only RPC (same name rules as joining, unique in the league, 40-char cap as
  M14's admin rename), logged; in League settings. Undo = rename back.
- **Bright tally for daylight**: a light, high-contrast theme for the tally board only, on by default outdoors-friendly
  or toggled on the board (builder's call); dark stays everywhere else. Tally stays motion-free.
- **"Needs you" dot fix**: on phones the gold dot on the team switch can sit scrolled out of sight; make it always
  visible (e.g. scroll the needing team into view, or show the count at the switch edge).

### 5.9 Tournament games in one go (admin)

- When setting up / opening a tournament, the admin sets **how many games** it has; the count is **editable** later.
  Games 1..N are created up front.
- **Opponents** can be filled in or changed **any time, before or during** (today's `set_game_opponent`, keepers +
  admins), shown as an editable list of the tournament's games in the admin/keeper tournament card.
- **Fantasy pairings stay Swiss**: game 1 paired at open, each later game paired when the game before it finishes
  (pairings are still computed in the browser and passed to `finish_game`; it now pairs the next existing game
  instead of creating it).
- **The tournament ends itself** when its last game is finished. This replaces the "That was the last game" checkbox
  (`p_last`) and the "Add game N+1" button (`add_next_game`), which are retired.
- Lowering the count deletes only **unstarted** games at the end; it can't go below games already started (my call).
  No confirm needed: re-raising the count recreates them (opponent names typed on a deleted game are lost; acceptable).
- Pick-notice emails keep working (they fire on pairings, which are still inserted per game).

### 5.10 Final UI overhaul (last)

After everything above ships, a final clean-up pass over the whole app (user, 2026-10-19). Scope is set at that time
with a short brainstorm and mockups, using the impeccable passes the user liked in M9 (critique → distill → polish,
**mockups after every stage**). Not designed here on purpose: it should react to what M15 actually built.

## 6. Constraints

- Builds on M14 (roster slots with `from_game`/`until_game`, removed teams, Users tab). Branch off main after M14 is
  live. Migrations continue from M14's 0024 (one migration per shipped phase, numbered at build time).
- Go-live order as always: user pastes the migration **before** pushing code that calls it.
- **Timing (my call):** M15 has no deadline and nothing in it is needed for CCCs (Nov 7–8). Phases that change the
  database (P3 rename, P4, P5, P6) go live **only while no tournament is open** (between tournaments). So there is no
  mid-tournament switch-over code: P4 never meets a half-run old-style tournament, P5 never meets a running
  tournament's open injuries. P5 still keeps past games' scores unchanged (§5.6). Front-end-only phases can ship any
  time except during a tournament weekend.
- Repo is public: never commit real stats CSVs or personal data.
- Tests follow repo norms: core/app vitest, PGlite DB tests, every new RPC in the rpc-gate test, calendar-proof
  fixtures (no `now()` in assertions).
- Phone first (375 px), dark theme, tokens.css only for design values (tokens.test enforces it).
- The live season is real (CCCs Nov 7–8). No test data in it; use the local simulation (`sim/`, untracked) or a
  throwaway season.
